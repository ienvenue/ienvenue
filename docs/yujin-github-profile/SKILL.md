# 陈瑜瑾的 GitHub 个人主页

仓库：`ienvenue/ienvenue`（公开），本地在 `/Users/yancy/code/github-profile`。
主页显示的是仓库根目录的 `README.md`。推到 `main` 后，主页马上更新。

这个主页是 chenyujin.top 在 GitHub 上的入口。它的任务只有一个：让访客一眼认出「这是陈瑜瑾」，然后去网站。所以它要像网站，而不是像一般的 GitHub 主页。

## 1. 风格：和网站同一个人

风格原则以 yujin-ui skill 为准（仓库 `chenyujin-web` 的 `docs/yujin-ui/SKILL.md`）：一眼看懂、态度优先、拒绝 AI 味、克制留白、每页视觉锚点不超过 5 个。这里只写 GitHub 上的具体做法。

现在的视觉锚点有 3 个：名字、格言、Prompt HUD 演示图。新增模块前先数一数，超过 5 个就要先删别的。

### 不放这些

| 不放 | 原因 |
|---|---|
| 打字动画、横幅 Banner、动图装饰 | 网站没有。动起来的东西会抢走视线 |
| Shields.io 徽章、技术栈图标墙 | 无意义图标。链接用纯文字就够 |
| 关注者数、提交统计、语言分布、连续提交天数 | 网站不写数字。数字会变，也不代表作品 |
| 贪吃蛇等贡献图动画 | 装饰，和作品无关 |
| emoji 清单（🔭🌱💬📫）、国旗 emoji | 千篇一律的模板感 |
| 名字下面的 `@ienvenue` 副标题 | GitHub 页面左边已经显示，重复 |
| 互动小游戏、自动抓取的动态看板 | 和「一眼看懂」相反 |
| 左右两栏表格排版 | 手机上很挤。改成上下排 |

用户明确要求时可以加，但先提醒它和网站风格冲突，等用户确认。

## 2. 内容：从网站原样搬

**文案的唯一来源是 chenyujin.top**（仓库 `/Users/yancy/code/chenyujin-web/public/`）。主页不自己写新说法。这样网站改了，主页跟着改就行，不会出现两套说法。

| 主页位置 | 网站来源 |
|---|---|
| 名字下面的口号 | 首页右下口号「学 AI 中实践，实践中学 AI。」 |
| 00 · 人生格言 | 关于我页 `about/index.html` 的格言和出处 |
| 01 · 在做 | 首页「01 · 在做」和轮播第 1 张：Prompt HUD 的说明句、「预约内测」（mailto）、「了解更多 →」 |
| 02 · 在用 | 首页「02 · 在用」和轮播第 2 张：Prompt Lib 的说明句和 3 条 Prompt 标题 |
| 演示图 | `chenyujin-web/public/assets/img/demo.png`，复制到本仓库 `assets/demo.png` |

- 搬之前先打开网站源文件核对原文，不凭记忆写。
- 网站上没有的句子，不要加。例如「沉浸式融入开发环境」「沉淀高阶思考框架」这类话。
- 英文是中文的翻译，用小字（`<sub>`）跟在中文后面。网站没有英文，所以英文是 AI 翻译的。新译的句子要在改前改后表里标出来，让用户确认。
- 网站的红线在主页同样适用：不写 Prompt 条数，不编造数据，不链接任何具体仓库（项目还没开源）。邮箱只用 `hi@chenyujin.top`。
- 网站文案变了，主页要同步。反过来，主页上发现文案问题，先告诉用户，改网站，再同步过来。

## 4. GitHub 的限制

GitHub 显示 README 时会清理 HTML，很多写法看起来有效，其实没用：

- `style="..."` 会被删掉。圆角、颜色、字号都设不了。小字用 `<sub>`，居中用 `<div align="center">`。
- 单个换行不会换行。要换行用行尾 `<br>`。
- 外部图片服务（统计卡等）挂了会显示坏图，所以不用。图片放仓库 `assets/`，用相对路径。
- GitHub 有深色模式。不要用白底图片或白底卡片，深色下会是一块白方块。
- 链接加不了 `target`，都在当前页打开。

## 5. 工作流程

1. **先复述。** 用自己的话说出用户的目标和想解决的问题，列出准备怎么改。用户确认后再动手。
2. **有歧义就问。** 编号列问题，每题给选项，推荐项放第一个。
3. **改 README。** 先拉最新：`git pull`。
4. **本地预览，截图给用户。** 运行本 skill 的 `scripts/preview.py`：
   ```bash
   python3 <本 skill 目录>/scripts/preview.py /Users/yancy/code/github-profile <临时目录>
   python3 -m http.server 8011 -d <临时目录>
   ```
   它用 GitHub 官方接口渲染，结果和主页上一致（样式是近似的）。改完 README 要重新运行，刷新页面不会更新。用户还要看的时候，不要关掉预览服务。
5. **列文案改前改后表。** 每条改动一行：改前、改后。AI 新译或新写的句子要标出来。用户逐条确认。
6. **本地提交，再问要不要推送。** 推送后主页立刻更新，所以推送前一定要问。提交说明用 `feat:` / `fix:` 开头，后面用中文一句话说清改了什么。
7. **删东西要谨慎。** 删分支、删 Actions 产物这类删了就恢复不了的操作，先问。默认留着不动。

## 6. 回复风格

- 用户没有开发背景。中文，短句，一句一个意思。技术术语保留英文，第一次出现时用一句话解释。
- 先给结论，再列细节。
- 查不到的写「未测」或「待确认」，不编造。
